# room3d — 3D-вьюер комнаты

`build_room_3d.py` берёт комнату в формате planhaus, считает геометрию тем же движком
(`tools/planhaus/scripts/room_spatial.py --json`) и пишет один HTML-файл на three.js 0.169
(подключается с cdn.jsdelivr.net): стены с проёмами, окна, двери с дугой открывания,
кухонные модули со столешницей и верхними шкафами, мебель, светильники, зоны, подписи.

```bash
python3 tools/room3d/build_room_3d.py rooms/kitchen-living.yaml -o viewer/kitchen-living.html
```

Дополнительные поля YAML для 3D описаны в начале `build_room_3d.py`.

## Помещения: одна модель для всех

Кухня-гостиная — обычное помещение, такое же, как коридор или ванная. У каждого помещения одни и те же части:
пол, стены, проёмы (окна и двери в стенах) и **объекты** (мебель, шкафы, техника, створки дверей).
В дереве справа каждое помещение — верхний узел с глазом (скрывает всё помещение) и папками «Стены»
(ножницы = срез, глаз = только пол и стены), «Проёмы» и папками объектов (по полю `group`, без него — «Объекты»).

Если рядом с `rooms/` лежит `apartment.yaml` с `frame: <id комнаты>`, вьюер рисует вокруг комнаты остальные
помещения: полы, стены (коробки `[x0, y0, x1, y1]` и `[..., z0, z1]` для перемычек и стен под окнами), стёкла
и `objects:` — всё в координатах этой комнаты (формат описан в самом `apartment.yaml`). По умолчанию остальные
помещения скрыты, кнопка «Все комнаты» слева показывает/прячет их сразу.

**Объект везде описывается одинаково.** Он стоит у стены своего помещения: `wall` (стена), `position`
(см вдоль стены от её первого угла), `gap` (отступ от стены, `< 0` — в стене), и три размера:
**ширина** (вдоль стены), **глубина** (от стены в комнату), **высота**, плюс `elevation` над полом.
Размеров «по оси X / по оси Y» нет: поля `x`, `y`, `sx`, `sy`, `against` и блок `items:` сборка отвергает.
Стены помещения для `wall:` — рёбра контура пола `A-B`, `B-C`, … (кухня — свои стены из YAML, остальные —
по порядку точек `floor`; буквы углов видны на сцене, а в `apartment.yaml` перечислены в комментарии над `objects:`).

## Контейнеры, наследование и ссылки

Чтобы не повторять числа и чтобы одно число тянуло за собой остальные, у объектов есть два механизма (одинаково во всех помещениях):

**1. Контейнер и наследование.** Объект с `type: group` (или `type: kitchen`) — контейнер без формы: он только собирает
вложенные объекты в дереве и хранит общие размеры. У вложенного объекта (`parent: <id контейнера>`) то, что не задано
(`height`, `depth`, `elevation`, `gap`, `top`), берётся у родителя, у родителя родителя и так далее; иначе — значение по умолчанию.
Своё значение у ребёнка перекрывает унаследованное.

```yaml
- {id: kitchen, type: kitchen, label: "Кухня", facade: "#d49b16", carcass: "#654a29", worktop: "#6b6259"}   # цвета всех `kitchen:`-шкафов
- {id: lower, type: group, parent: kitchen, height: 90, depth: 60, top: 4}   # нижняя часть: высота, глубина и столешница шкафов
- {id: e-base, parent: lower, wall: B-C, position: 144, width: 162, kitchen: true}   # высота 90, глубина 60, столешница 4 — от `lower`
```

**2. Ссылки.** Любое число можно заменить формулой в кавычках, начинающейся с `=`. Голое имя — свойство самого объекта, `id.имя` —
свойство другого объекта или проёма этого помещения (в том числе `params` контейнера): `"=lower.height + lower.top"`,
`"=portal.width + 1"`, `"=upper.level - elevation"`. Действия `+ - * /` и скобки; вокруг минуса — пробелы (в id бывают дефисы).
Унаследованная формула считается для того ребёнка, на котором она оказалась (так «верх верхних шкафов 260» превращается в
высоту каждого шкафа: `260 − его elevation`). У проёма ссылкой может быть только `height` (`position` и `width` читает движок правил).
Свои числа контейнера — `params: {level: {value: 260, label: "Верх шкафов от пола"}}`.

В вьюере у вычисленного поля замок 🔗: поле недоступно, меняйте источник (например «Нижняя часть» → высота) или нажмите замок и задайте
значение вручную (🔓 вернёт привязку). Перетаскивание объекта стрелками тоже заменяет ссылку числом. Клик по имени контейнера в дереве
выбирает его (подсвечиваются все вложенные объекты) и сворачивает/разворачивает. Опечатка в ссылке, родитель не контейнер, цикл —
ошибка сборки. Размеры по осям по-прежнему запрещены: у объекта всегда ширина, глубина и высота.

Каждая стена — своя строка в дереве. Ножницы у строки = срез: стена прячется, когда камера смотрит на неё снаружи
(стены квартиры — когда стоят между камерой и точкой, вокруг которой она вращается). Иконка стены = видна всегда,
с обеих сторон. Ножницы в заголовке папки переключают все её стены. Коробки одной стены квартиры (стойки и
перемычка двери, стена под и над окном, стекло в ней) вьюер сам склеивает в один объект: одинаковая толщина и
касаются вдоль стены. Настройка хранится в браузере, как скрытые объекты.
«Просмотреть YAML» выдаёт блоки `objects:` для `rooms/<id>.yaml` и для каждой комнаты `apartment.yaml`
(в одном формате). Другой файл квартиры: `--apartment path.yaml`.

**Сохранение правок на сервере.** Вьюер запускать через `py -3.11 tools/room3d/serve.py [--port 8765] [--bind 127.0.0.1]`
(в `.claude/launch.json` это конфигурации `planner` и `planner-2`). Любая правка (поля, цвета кухни, окна и проёмы) через
~0,5 с уходит на `POST /api/save`, и сервер вносит её прямо в `rooms/<id>.yaml` / `apartment.yaml`: меняются только строки
`ключ: значение` этого объекта, комментарии и порядок остаются. Строка внизу панели показывает статус («✓ Сохранено в YAML»).
Страница, открытая с сервера, всегда собрана из актуального YAML (сервер пересобирает её, если YAML или шаблон новее), поэтому
во всех браузерах данные одинаковые. На сервер уходит только разница с YAML, так что старая вкладка не затирает чужие правки.
Скрытые объекты, камера и срезы стен остаются настройкой браузера. Без `serve.py` (файл напрямую, другой статический сервер)
правки, как раньше, лежат в `localStorage` и переносятся через «Просмотреть YAML». В git сервер ничего не коммитит.
Эндпоинт без авторизации: `--bind 0.0.0.0` только в доверенной сети.

**Перемещение и поворот мышью.** Клик по предмету или проёму на сцене выбирает его (оранжевая рамка) и показывает стрелки
перемещения; каждый следующий клик по нему же переключает дальше: кольцо поворота → контролы пропадают (выбор остаётся) →
снова стрелки. У проёма поворота нет. Выбор другого предмета, клик по пустому месту или Esc убирают контролы; выбор из списка
в дереве показывает только рамку. Gizmo — готовый `TransformControls` из three.js
(`three/addons/controls/TransformControls.js`), режим translate в осях стены, у которой стоит предмет: красная стрелка — вдоль стены
(`position`), зелёная — вверх (`elevation`, у окна `sill`), синяя — от стены / к стене (`gap`); квадраты между стрелками
двигают по двум осям сразу. Gizmo двигает невидимую точку в центре коробки предмета, а вьюер переводит её положение
обратно в поля `position / gap / elevation` — поэтому границы, отмена (Ctrl+Z, один шаг на всё перетаскивание),
сохранение в браузере и «Просмотреть YAML» работают так же, как с ползунками. Шаг 0,5 см. Дверь двигается только вдоль стены.

**Поворот объекта.** Поле `rotation` (градусы **по часовой стрелке при взгляде сверху**, вокруг центра коробки объекта,
по умолчанию 0; в YAML ноль не пишется). Кольцо поворота ставит значение с шагом 45°, в поле «Поворот» можно ввести любой угол.
Объект остаётся описан стеной, `position`, `gap`, шириной × глубиной × высотой — поворачивается только его картинка, а границы
`position` / `gap` считаются по неповёрнутой коробке (повёрнутый предмет может выступить за стену). Выем `cutout` не
поворачивается вместе с объектом, движок правил зазоров (`room_spatial.py`) объекты `objects:` не проверяет.

Проверка без доступа к CDN (облачная сессия): поставить `three@0.169.0` через npm во временную
папку и в Playwright перехватить запросы `https://cdn.jsdelivr.net/npm/three@0.169.0/**`,
отдавая файлы из `node_modules/three/`. Страница выставляет `window.__ready = true`, когда сцена построена.

Проверено на демо-комнате planhaus:
`python3 tools/room3d/build_room_3d.py tools/planhaus/sample-project/rooms/living-room.yaml -o viewer/sample-living-room.html`

## 3D-модели вместо коробок

У объекта в `objects:` можно указать `model: assets/models/<name>.glb` — сборщик встроит GLB прямо в HTML,
а вьюер впишет модель в коробку объекта (ширина вдоль стены, глубина от стены, высота; перед модели (+Z в glTF)
смотрит в комнату). `cutout: {in: <id>, width, depth}` вырезает отверстие в корпусе и столешнице другого
объекта (мойка в нижнем шкафу). Модель производителя в .3ds конвертируется так (нативный .max — `max_to_glb.py`, рецепт в CLAUDE.md):

```bash
python3 tools/room3d/tds_to_glb.py model.3ds -o assets/models/name.glb --scale 0.001 --mat ma3=#c9ccce:0.7:0.32
```

`--scale` — перевод единиц файла в метры (мм → 0.001), `--mat имя=#цвет:metalness:roughness` — материалы
(в .3ds нет PBR-данных); скрипт печатает размеры модели в см — их и ставить в `width/height/depth`.

## Окно, радиатор, ТВ, тумба, ковёр

- **Окно** рисуется как белый ПВХ-стеклопакет: рама, импост, глухая створка или поворотная (своя рама и ручка у импоста),
  двойное остекление с дистанционной рамкой, подоконник с «ушами». Поля окна: `mullion` (см от края окна у первого угла стены
  до оси импоста; нет — одна створка), `opens: start | end | both | none` (какая створка открывается), `frame_color`.
- `type: radiator` — стальной панельный радиатор: профилированный фасад, решётка сверху, термоголовка (`valve: start | end`).
- `type: tv` — плоский ТВ на подставке: ширина × глубина (подставка) × высота (общая), `panel` — толщина панели,
  `stand` — высота подставки. Экран — настоящее зеркало (`Reflector` из three.js): отражает комнату в перспективной
  камере; в ортогональной виден глянцевый чёрный экран.
- `doors: N` + `facade` у обычного объекта-коробки — N одинаковых дверец на лицевой стороне (тумба, комод), корпус — `color`.
- `type: rug` — ковёр с потёртыми полосами вдоль ширины, `color` — основной цвет, `height` — ворс.
- Ссылки могут указывать и на окна: `position: "=window.position + 6"`.
